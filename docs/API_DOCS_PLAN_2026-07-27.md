# Plan — Simulate API documentation (`api_docs/`, use-case JSON + eye-toggle viewer)

**Date:** 2026-07-27 · **Status:** plan, not yet executed · **Executor:** Claude Haiku 4.5, start to finish, one stage at a time · **Reference implementation:** `../last_mile_user/api_docs/` (see its `README.md`, `USE_CASE_MAP.md`, `SCHEMA.md`, `tools/build_docs.py`, `tools/capture_session.py` — read all five before Stage 0).

## Goal

Two documentation sets, same pattern as `last_mile_user/api_docs/`: internal, unredacted, one JSON file per distinct use case, a self-contained HTML viewer with eye-toggle masking, freshness badges, and a call-site chain back to real code.

- **Part A — Internal API.** Simulate's own FastAPI backend (`api/app/*`, 13 routers, 91 routes) that `web/` (the Next.js dashboard) calls. **No prior art exists for this** — it is undocumented today.
- **Part B — External API.** The Fainzy/LastMile APIs simulate calls *as a client* (`transport.py`, `user_sim.py`, `store_sim.py`). Prior art exists at `docs/last_mile_api_inventory.md` (narrative, no live capture, no code citations) — Part B upgrades it to the use-case-JSON + live-capture + viewer format, cross-checked against current code.

Both parts live under one `simulate/api_docs/` tree with an `internal/` and `external/` split, so the viewer can toggle between "API simulate serves" and "APIs simulate calls."

## Do not start Stage 4 or Stage 5 until these are resolved

These are exactly the kind of load-bearing facts the no-assumptions rule (see the operator's global `CLAUDE.md`) forbids guessing. Haiku must stop and ask the user for each, in chat, before the stage that needs it — not invent a plausible answer and move on.

1. **Internal capture target (blocks Stage 4).** Which local/dev database and auth account should `capture_internal.py` hit? It must **never** point at a production `DATABASE_URL`. The user must supply: (a) confirmation of how to start a local dev server safely, (b) a dev/test login (username+password) for `POST /api/v1/auth/login`, or a way to seed one. Read `api/app/auth/dependencies.py` and `config.py` for the real config keys — do not guess env var names.
2. **External capture target (blocks Stage 5).** This hits real `fainzy.tech`/`lastmile.fainzy.tech`, same risk profile as `last_mile_user`'s plan: places and cancels one real order, may send real SMS OTPs. The user must confirm: a throwaway/test phone number to use, and explicit go-ahead to run the mutation phase. Default to **read-only capture only** (no `--include-mutations`, no `--danger`) unless the user opts in.
3. **Stage 6 (viewer) capability gate.** `last_mile_user`'s plan explicitly paused before its HTML-viewer stage and required a switch to Opus, because the recursive JSON-tree renderer with per-field eye toggles was "the fiddly part." This plan is written for Haiku end-to-end per the user's request, but Stage 6 below includes an explicit fallback to a simpler, non-recursive viewer if the full version doesn't converge in one focused attempt. Do not silently ship a broken or half-wired viewer and call the stage done — degrade scope on purpose and say so in `api_docs/README.md`.

If the user hasn't answered #1 or #2 by the time those stages come up, stop and ask — do not substitute your own dev credentials, DB, or phone number.

Naming rule, redaction mechanism, and per-file JSON schema shape: copy `last_mile_user/api_docs/SCHEMA.md` verbatim as the starting point, then add one field simulate needs that last_mile_user didn't: `"part": "internal" | "external"`. Everything else (`useCase`, `group`, `endpoint`, `usedIn.chain`, `trigger`, `params`, `auth`, `sensitivePaths`, `alsoTriggeredBy`, `capture`, `response`) carries over unchanged — read the real file, don't retype it from memory.

## Auth models (read from code, do not assume)

- **Internal (Part A):** session-cookie auth. Cookie name is `SESSION_COOKIE_NAME`, defined in `api/app/auth/dependencies.py` — read the actual value, don't guess it. Obtained via `POST /api/v1/auth/login` (`api/app/auth/routes.py:41`). `GET /api/v1/auth/session` / `/me` (routes.py:118-119) return the current identity — use these to verify a captured session is real before trusting the rest of the run.
- **External (Part B):** unchanged from `docs/last_mile_api_inventory.md` — `Fainzy-Token` for `fainzy.tech`, `Authorization: Token <token>` for `lastmile.fainzy.tech`. Simulate already has a working authenticated client for both in `transport.py`; reuse it, don't reimplement the auth handshake in a new script.
